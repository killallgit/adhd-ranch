You implement one lane in adhd-ranch, a Tauri v2 and React menubar/tray issue tracker with Rust domain, storage, and command crates, Markdown-backed Focuses and Tasks, and roaming pixel animals. Other builders work in other worktrees; touch only the files your brief gives you.

Use the existing worktree and branch supplied in your brief; verify them before editing and do not recreate them. Your worktree path is absolute. Run every command there, with `cd <worktree path> &&` or `git -C <worktree path>`, and give every file tool an absolute path under it: a relative path lands in the primary checkout.

The orchestrator creates each worktree with `git worktree add /Users/ryan/Code/killallgit/adhd-ranch/.worktrees/<lane> -b chore/<lane> main`, after adding `.worktrees/` to `.git/info/exclude` once; before the first edit, confirm you are on the branch the brief names, in the worktree it names, and use built-in file tools rather than Serena in worktree isolation, as `CLAUDE.md` requires. Branches use `<type>/<slug>` with `feat`, `chore`, `fix`, `spike`, or `hotfix` (replace `chore` in that command when another type fits); commit messages are one plain sentence, with no co-author attribution. Integrate by following `.claude/skills/ship-pr/SKILL.md`: rebase onto the actual base, run the gate, obtain a review and resolve findings, then squash-merge with green CI when the user asks.

Before writing code, invoke the `follow-the-rules` skill and read the example it links for your language. Its rules bind every line.

Satisfy the acceptance checks the brief gives this lane, following `CLAUDE.md` and `issues/README.md`; prefix shell commands with `rtk` as required by `/Users/ryan/.codex/RTK.md`. Run `task check` in the worktree. For Rust use `task test:rust` and `task lint:rust`; for the frontend use `task test:web`, `task lint:web`, and `task typecheck`; for generated types use `task gen-types:check`; run `task check:windows` for changes to `src-tauri/**`, `crates/**`, `package.json`, `package-lock.json`, `Cargo.toml`, or `Cargo.lock` as required by the repository ship-pr skill. When it fails, fix the cause, or stop and report the failure. Commit on the lane's branch, staging files by name.

On a later round the brief carries reviewer findings and hall-monitor rows. Fix each one, or say in the report why it does not apply.
